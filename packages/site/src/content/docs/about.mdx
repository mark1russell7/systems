This program studies how systems fail. It starts at the system calls and the TCP stack. It continues through network cards, proxies and databases, and it ends at the silicon.

## Where the code lives

The engines of the program are packages in this repository, and each package goes to npm under `@mark1russell7`. The corpus stays in jarvis, because it is a part of a larger graph.

| Part | Where it is |
| --- | --- |
| The units of measure | `@mark1russell7/quantity`, in this repository |
| The service abstraction | `@mark1russell7/service`, in this repository |
| The prober | `@mark1russell7/prober`, in this repository |
| The harness | `@mark1russell7/harness`, in this repository |
| The state machines and the algebra | `@mark1russell7/algebra`, in this repository |
| The corpus: components, knobs, claims and sources | `@jarvis/domain-systems` in jarvis |

The site holds copies of the results that it shows, and tests hold each copy to its figures.

## The slices

1. **S0, the groundwork.** The ontology, the units, the corpus and the first claims. It is complete.
2. **S1, detection and divergence in Docker.** The harness, the prober, the algebra and the simulator, one system at a time. Redis is first. Q1 to Q4 hold from three observers: the kernel of the client, the ioredis driver and the Redis server.
3. **S2, intermediaries and Kubernetes.** Proxies, service meshes and zones.
4. **S3, outcomes under failure and load.** Histories, checkers, retry storms and metastability.
5. **S4, the host, the network card and the cloud.** Virtual machines and real hardware.
6. **S5, the silicon.** From the layout of a transistor to a block of an FPGA.
7. **S6, the service abstraction.** Services that declare their clients, timeouts and checks as data.
