## One question, three answers

Linux 6.6 has default settings for each TCP timer. With these settings, an idle connection learns of a black hole after 2 h 11 min 15 s. A connection with a request in flight learns after 924.6 s. A connection to a frozen process does not learn of the failure at the TCP level.

The lab below computes these times from the rules of the kernel. Select a harness cell to see the runs that the harness measured. Change a setting to see the new prediction.

## The parts of the program

<CardGrid>
  <Card title="A corpus" icon="open-book">
    Each fact about a system is a claim. A claim has a unit, the conditions where it is true, its sources and its grade of evidence.
  </Card>
  <Card title="An algebra" icon="seti:config">
    The algebra reads the state machines and the settings. It gives each timer a closed form, and a band for how late the timer fires.
  </Card>
  <Card title="A harness" icon="rocket">
    The harness starts each cell in fresh containers. It injects a fault, measures the result on one clock, and compares the result with the prediction.
  </Card>
  <Card title="A prober" icon="magnifier">
    The prober is an eBPF program. It records what the kernel does to each socket, to the nanosecond.
  </Card>
</CardGrid>
